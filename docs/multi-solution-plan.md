# 一题多解方案（待实施）

> 状态：**方案已定，暂不实施**（2026-11-16 记录）
> 触发原因：用户反馈「一题多解只保留了一种」，且同一解法重复提交无法去重

---

## 一、问题

当前一道题只能存一种解法，且存在三个层次的问题：

| 层级 | 问题 | 后果 |
|---|---|---|
| 存不下 | md 结构事实上一题一解，`writeCodeToMd()` 遇到已有代码直接 `return false` | 第二条解法永远进不来 |
| 分不清 | OJ 上「同一解法改三次再交」和「三种不同算法」在数据里长得一样，都是 N 条 AC 记录 | 无法自动区分多解与重复 |
| 修不掉 | 因为「有代码就跳过」，历史错配会永久固化 | 1148/1327/1403/1404 那批他题代码一直没被发现 |

## 二、现状数据（2026-11-16 实测）

| 项目 | 数值 |
|---|---|
| 博宜题解 | 1215 道：1207 道各 1 个代码块，8 道无代码 |
| 洛谷题解 | 1044 道：1039 道 1 块，5 道 2 块 |
| 全站「解法二」标记 | 仅 3 个文件，且格式不统一 |

结论：目前全站事实上是「一题一解」，多解格式没有约定。

## 三、方案

### 3.1 数据模型：正文多解，front matter 只存同步状态

```markdown
---
title: "1083 - 回文数"
tags: ["模拟", "字符串"]
difficulty: 入门
source: dfboy
problem_id: 1083
synced_sources: [7327063, 7186354]   # 已同步的提交ID，用于增量判断
---

## 题目描述
...

## 解题思路
...

## AC 代码

### 解法一：模拟加颠倒数（O(k·log n)）
```cpp
...
```

### 解法二：字符串翻转判断（O(k·n)）
```cpp
...
```
```

**设计理由**：单一数据源在正文。解法标题、复杂度写在 `###` 里，marked 与预渲染天然支持，无需改渲染器；front matter 只放 `synced_sources` 做增量标记，避免正文与元数据双写不同步。

### 3.2 去重：只自动做「精确去重」，模糊的留给人工

| 层级 | 规则 | 处理方式 |
|---|---|---|
| L1 精确 | 去注释、压空白后**完全相同** | 自动合并，只留一份 |
| L2 近似 | 归一化后相似度 > 90% | **不自动合并**，标记「疑似重复」待人工确认 |
| L3 不同 | 相似度低 | 都保留为独立解法 |

**为什么 L2 不自动合并**：同一算法改几个变量名会到 95%，但两个都用双层循环的不同算法也可能有 85%。自动合并会误杀，题解站的内容质量不能赌。

### 3.3 抓取流程改造（关键）

```
取 /p/{pid} 的全部 AC 提交 → 过滤 C++ → 逐个下载代码
  → 归一化分组（L1 去重）得到 N 个候选解法
  → 与 md 现有解法比对：
       已存在        → 跳过
       新解法        → 追加「解法N」
       md 里有但 OJ 上找不到对应提交 → 标记「来源未知」，保留不删
  → 写回 synced_sources
```

这一改同时解决三件事：多解能进来、重复提交被去重、错配代码会被发现（OJ 上找不到对应提交，会被标记「来源未知」）。

### 3.4 展示层

- 详情页顶部：`本题有 3 种解法` + 锚点跳转
- 每个解法独立 `###` 标题，自动生成目录
- 预渲染页全部展开（SEO 完整）
- 索引 `index.json` 增加 `solutionCount`，列表可显示「3 解」徽标

## 四、分阶段实施

| 阶段 | 内容 | 影响面 | 预估 |
|---|---|---|---|
| P0 | 定格式 + 挑 1 道有多解的题做样板 | 单个文件 | 1–2 小时 |
| P1 | 改抓取脚本（多解 + L1 去重 + source 记录） | 脚本，不动数据 | 半天 |
| P2 | 前端多解展示 + 预渲染目录 | 前端 | 半天 |
| P3 | 历史回填（可选，1215 道重跑） | 全量数据 | 30–40 分钟抓取 |

P1 完成后**新抓取的题即支持多解**，历史题可按需回填，不必一次性动 1215 道。

## 五、需要拍板的四点

| # | 待决策 | 建议 |
|---|---|---|
| ① | 一道题最多留几个解？ | 上限 4 个，超出按代码差异度挑最不像的（教学场景下解法太多反而干扰） |
| ② | 解法标题怎么来？ | 自动只能出「解法一/二/三」；可尝试按代码特征猜算法名（含 `sort`→排序、含 `dp[`→动态规划、有递归→递归），准确率约七成，需人工校正 |
| ③ | 历史 1215 道要不要全量回填？ | 建议先做新题 + 重点题，其余按需。全量会明显增加 md 体积与构建时间 |
| ④ | 洛谷侧是否统一？ | 可以顺手把洛谷那 5 个双代码块文件对齐新约定 |
