1Base64 编码解码

Base64 是一种将二进制数据转换为可打印 ASCII 字符的编码方案。 它使用 64 个字符：A-Z（索引 0-25）、a-z（26-51）、 0-9（52-61）、+（62）、/（63）， 以及填充字符 =。

核心规则

编码：每 3 字节（24 位）划分为 4 组，每组 6 位， 查表得到 4 个 Base64 字符。
解码：每 4 个 Base64 字符反向查表得到 4 个 6 位值， 合并为 24 位，还原为 3 字节。
若原数据不是 3 的倍数，末尾补 0 并用 = 填充。

分步示例：编码 "Man"

明文 "Man"（3 字节），ASCII 码：M=77、a=97、n=110。

1 将 3 字节拼成 24 位二进制：
M = 77 = 01001101   a = 97 = 01100001   n = 110 = 01101110
拼接：01001101 01100001 01101110
2 每 6 位一组，分成 4 组：
010011 | 010110 | 000101 | 101110
十进制：19   22   5   46
3 查 Base64 编码表：
19 → T   22 → W   5 → F   46 → u
编码结果：TWFu
Base64 编码表速记：A-Z（0-25）、a-z（26-51）、0-9（52-61）、+（62）、/（63）。 初赛中编码表通常以数组形式给出。

2RLE 行程编码 (Run-Length Encoding)

RLE（行程编码）是一种简单的无损压缩算法。 它将连续重复的字符记录为 重复次数 + 字符 的形式。

编解码规则

编码方向（压缩）：aaabbc → a3b2c1 （连续重复字符替换为"字符+重复次数"）

解码方向（解压）：a3b2c → aaabbc （读取"字符+次数"，输出连续字符序列）

注意：次数可能超过一位数，如 a12 表示 12 个 a；有时次数为 1 可省略不写。

分步示例：解码 a3b2c

1 读入编码串 a3b2c
2 遇到 a，读后面数字 3，输出 aaa
3 遇到 b，读后面数字 2，输出 bb
4 遇到 c，后面无数字（或数字为1），输出 c
5 最终解码结果：aaabbc
真题注意：2025 年阅读第 4 题考查 RLE 解码的完善程序，需要填写 5 处空缺。 关键逻辑包括：读取字符、拼接多位数字、按次数输出字符。

3Boyer-Moore 多数派投票算法

Boyer-Moore 多数派投票算法用于在数组中查找出现次数超过一半的元素（多数元素）。 时间复杂度 O(n)，空间复杂度 O(1)。

核心思想：候选者消除法

维护一个候选者（candidate）和一个计数器（count）：
• 遍历数组，若 count == 0，将当前元素设为候选者，count = 1。
• 若当前元素 == 候选者，count++；否则 count--。
• 遍历结束后，候选者就是潜在的多数元素。
• 第二遍遍历验证该候选者是否真的出现次数超过一半。

分步示例：数组 [3, 3, 4, 2, 3, 3, 5, 3]

步骤当前元素countcandidate说明
1313count=0，选 3 为候选者
2323等于候选者，count++
3413不等于，count--
4203 → 取消count 归零
5313count=0，选 3 为候选者
6323等于候选者，count++
7513不等于，count--
8323等于候选者，count++

结果：候选者 = 3，最终 count = 2。 第二遍遍历统计 3 出现的次数为 5 次（超过 8/2=4），确认 3 是多数元素。

核心代码框架（初赛常考）：
int candidate = 0, count = 0;
for (int x : arr) {
  if (count == 0) candidate = x;
  if (x == candidate) count++;
  else count--;
}

4欧拉筛 / 线性筛

欧拉筛（线性筛）是线性时间复杂度O(n) 的质数筛法。 其核心思想是：每个合数只被其最小质因子筛掉一次。

与埃氏筛的区别

• 埃氏筛：每个质数的倍数都被标记，合数可能被多次标记。
• 欧拉筛：每个合数只被最小质因子筛掉一次，时间复杂度严格 O(n)。
• 欧拉筛还可以在筛法过程中同时求出因数个数和因数和。

线性筛模板（求质数）

const int N = 1000000; bool is_prime[N+1]; int primes[N], tot; void euler_sieve(int n) {   for (int i = 2; i <= n; i++) {     if (!is_prime[i]) primes[tot++] = i;     for (int j = 0; j < tot && primes[j] * i <= n; j++) {       is_prime[primes[j] * i] = true;       if (i % primes[j] == 0) break; // 保证每个合数只被最小质因子筛掉     }   } }

分步示例：n = 20 的筛法过程

1 i=2：质数，primes=[2]；标记 2×2=4 为合数；i%2==0，break
2 i=3：质数，primes=[2,3]；标记 3×2=6、3×3=9；i%3==0，break
3 i=4（合数）：primes=[2,3]；标记 4×2=8；i%2==0，break（不标记 4×3=12，因为 12 的最小质因子是 2，由 6×2 筛掉）
4 i=5：质数，primes=[2,3,5]；标记 5×2=10、5×3=15、5×5=25（>20 停止）
5 i=6：primes=[2,3,5]；标记 6×2=12；i%2==0，break（不标记 6×3=18，18 应由 9×2 筛掉）
... 以此类推，直到 i=20
求因数个数与因数和

在欧拉筛过程中，维护 cnt[i]（i 的最小质因子次数）和 sum[i] 可以同时求出每个数的因数个数和因数和：
• 设 n = p1a1 × p2a2 × ...
• 因数个数：(a1+1)(a2+1)...
• 因数和：(1+p1+...+p1a1)(1+p2+...+p2a2)...

📖 真题 · 2021 · 阅读第2题 Base64 解码过程理解
2021 年 CSP-J 阅读程序第 2 题给出了 Base64 编码表 table[64] 并实现了解码函数。已知解码表中字符 'A' 对应值 0、'B' 对应 1、 'a' 对应 26、'0' 对应 52、'+' 对应 62、 '/' 对应 63。以下关于解码过程的说法错误的是？
A 解码时将每 4 个字符还原为 3 个字节
B 遇到 '=' 表示填充，不参与解码
C 解码时要把字符查表得到的 8 位值拼接起来
D 原数据长度不是 3 的倍数时需要填充
正确答案：C
解析：

A → 正确。Base64 解码规则：4 个字符 → 3 个字节。
B → 正确。字符 '=' 表示末尾填充，不参与解码运算。
C → 错误。解码时查表得到的是6 位值（不是 8 位）， 4 个 6 位值共 24 位再拆分为 3 个 8 位字节。
D → 正确。原数据不足 3 的倍数时末尾补 0， 编码后用 '=' 填充到 4 的倍数。

考点总结：Base64 编码用 6 位表示一个字符， 解码时反向查表得到 6 位值，不是 8 位！

A Tm8=
B Tm9
C Tm9=

正确答案：A · Tm8=

① N=78 = 01001110，o=111 = 01101111
② 拼接 16 位：01001110 01101111
③ 每 6 位分组（末尾补 0 到 24 位）：
  010011 | 100110 | 111100 | 000000（补零）
  十进制：19   38   60   0

  19 → T   38 → m   60 → 8   0 → A
⑤ 原数据 2 字节，不足 3 的倍数，末尾补 =：Tm8=

注意：最后一组全为 0 时查表得到 A（不是直接填 =）， 只有填充的等号才用 = 表示。这里原数据 2 字节，编码成 3 个有效字符 + 1 个 =。
📖 真题 · 2025 · 阅读第4题（完善程序） RLE 行程编码解码
2025 年 CSP-J 完善程序第 4 题考查 RLE 解码。给定编码串 s （如 "a3b2c5"），需要将其解码为原始字符串。以下哪段逻辑是正确的解码核心过程？ （假设 i 为当前扫描位置，result 存储解码结果）
A while (i<s.size()) { ch=s[i++]; cnt=0; while (isdigit(s[i])) cnt=cnt*10+(s[i++]-'0'); for (int k=0;k<cnt;k++) result+=ch; }
B while (i<s.size()) { ch=s[i++]; cnt=s[i++]-'0'; for (int k=0;k<cnt;k++) result+=ch; }
C while (i<s.size()) { cnt=s[i++]-'0'; ch=s[i++]; for (int k=0;k<cnt;k++) result+=ch; }
D while (i<s.size()) { ch=s[i++]; cnt=1; while (isdigit(s[i])) cnt=cnt*10+(s[i++]-'0'); for (int k=0;k<cnt;k++) result+=ch; }
正确答案：A
选项分析：

A ✓ 先读字符，再拼接多位数字（如 "12" 解析为 12）， 最后输出 cnt 个字符。正确处理了多位数和字符与数字的顺序。

B ✗ 只读一位数字。编码 "a12" 会被错误解析为次数 1 和字符 '2'。

C ✗ 先读数字再读字符，顺序错误。编码 "a3" 会先把 'a' 当数字读，结果错误。

D ✗ cnt 初始为 1，若编码为 "a3"，执行后会先输出一次 a 再输出 3 次 a，共 4 次，错误。

考点：RLE 解码的关键是正确拼接多位数字，且字符和数字的读取顺序不能搞反。 a12b3 应先取字符 'a'，再拼出 12，输出 12 个 a。

A 15

📖 真题 · 2025 · 完善第2题 Boyer-Moore 多数派投票
2025 年 CSP-J 完善程序第 2 题考查 Boyer-Moore 投票算法。 以下程序寻找数组 a[0..n-1] 中出现次数超过一半的元素（假设一定存在）。 空白处应填入？
int candidate = 0, count = 0; for (int i = 0; i < n; i++) {   if (count == 0) {     candidate = a[i];     count = 1;   } else if (a[i] == candidate) {     // 填空处   } else {     count--;   } }
A count = 0
B count++
C candidate = a[i]
D count = count
正确答案：B · count++
算法逻辑分析：

Boyer-Moore 投票算法的三种情况：

• 情况1（count == 0）：当前候选者被淘汰，选新候选者。
• 情况2（a[i] == candidate）：当前元素与候选者相同，支持票 +1 → count++
• 情况3（a[i] != candidate）：当前元素与候选者不同，抵消一票 → count--

错误选项：
A ✗ count = 0 会丢失已经累计的票数。
C ✗ 候选者不需要更换（相同元素不应更换候选者）。
D ✗ count = count 等于没操作。

考点：这段代码是 2025 年完善程序的经典填空，需要理解"支持则加一、反对则减一"的核心逻辑。

📖 真题 · 2021 · 阅读第3题 欧拉筛求因数个数与和
2021 年 CSP-J 阅读程序第 3 题使用欧拉筛计算每个数的因数个数和因数和。 已知代码中维护了 cnt[i]（i 的最小质因子次数）和 sum[i]。 对于 i = 12（质因数分解为 22 × 31）， 其因数个数和因数之和分别是？
A 因数个数=6，因数和=24
B 因数个数=5，因数和=28
C 因数个数=6，因数和=28
D 因数个数=4，因数和=24
正确答案：C · 因数个数=6，因数和=28
公式推导：

12 = 22 × 31

因数个数公式：(a1+1)(a2+1)...(ak+1)
= (2+1) × (1+1) = 3 × 2 = 6

12 的因数：1, 2, 3, 4, 6, 12（共 6 个）✓

因数和公式：(1+p1+p12+...+p1a1) × (1+p2+...+p2a2) × ...
= (1+2+22) × (1+3) = (1+2+4) × 4 = 7 × 4 = 28

验证：1+2+3+4+6+12 = 28 ✓

考点：初赛常考利用线性筛维护因数信息的原理，需要熟记因数个数和因数和的公式。
✎ 模拟题 欧拉筛执行过程理解
使用欧拉筛（线性筛）求 n=30 以内的质数。当 i = 15 时， 内层循环会标记哪些数为合数？（已知 primes = [2,3,5,7,11,13]）
A 标记 30，然后 break
B 标记 30、45，然后 break
C 标记 30、45、75
D 标记 30
正确答案：A · 标记 30，然后 break
欧拉筛核心逻辑分析：

当 i = 15 时，遍历质数列表：

• j=0, primes[0]=2 → 2×15=30（≤30），标记 30 为合数。
  15 % 2 ≠ 0，继续。

• j=1, primes[1]=3 → 3×15=45（>30），超出范围，循环结束。

但实际上，因为 15 % 2 ≠ 0，还会检查下一个质数 3。
3 × 15 = 45 > 30，所以内层循环到此结束。

等等，再仔细看：15 % 2 ≠ 0，所以不会 break。 继续下一个质数 3，但 3×15=45>30，循环结束。

所以只标记了 30 为合数。

关键理解：i % primes[j] == 0 时才 break。 i=15 时，15%2=1≠0，不会在 2 处 break，但 3×15 已超出 n=30，自动结束。

对比：若 i = 12，primes=[2,3,5,7,11]：
• 2×12=24，标记；12%2==0 → break（不标记 3×12=36）。 因为 36 的最小质因子是 2，应由 18×2 来筛掉。
✎ 综合模拟 四种特殊算法识别
以下关于四个特殊算法的描述，错误的是？
A Base64 用 6 位二进制对应一个可打印字符，每 4 个字符还原为 3 字节
B RLE 编码中 "a10" 表示 10 个连续的字母 a
C Boyer-Moore 算法在找不到多数元素时返回候选者，但需要第二遍验证
D 欧拉筛中每个合数可能被多个质因子标记多次
正确答案：D
逐项分析：

A → 正确。Base64 用 6 位（26=64）对应一个字符， 4 个字符共 24 位，还原为 3 个 8 位字节。

B → 正确。RLE 编码 "a10" 表示字母 a 重复 10 次。

C → 正确。Boyer-Moore 第一遍找出可能的候选者， 第二遍必须验证其出现次数是否真的超过一半。

D → 错误。欧拉筛（线性筛）的核心特点就是每个合数只被最小质因子标记一次， 这正是它比埃氏筛高效的原因。通过 if (i % primes[j] == 0) break 保证每个合数只被筛一次。

拓展：埃氏筛中合数 30 会被质数 2、3、5 各标记一次（共 3 次）， 而欧拉筛中 30 只在 i=15, primes[j]=2 时标记一次。
✎ 综合模拟 算法复杂度与特征识别
已知四种算法的时间复杂度如下。将算法与复杂度配对，正确的是？

算法：
① Base64 编码 n 字节数据   ② RLE 解码长度为 n 的编码串
③ Boyer-Moore 投票   ④ 欧拉筛求 1..n 的质数

复杂度：
I. O(n)   II. O(n)   III. O(n)   IV. O(n)
A 都是 O(n)，但常数不同
B ①是 O(n)，②是 O(n2)
C ③是 O(n2)，④是 O(n log log n)
D ②是 O(n)，④是 O(n log log n)
正确答案：A · 都是 O(n)，但常数不同
详细分析：

• ① Base64 编码/解码：每 3 个字节编码为 4 个字符（或逆过程）， 遍历一次数据即可完成，O(n)。

• ② RLE 解码：只需扫描编码串一次，拼接数字、输出字符， 注意输出字符的总数可能远大于编码串长度，但扫描编码串本身是 O(n)。

• ③ Boyer-Moore 投票：第一遍遍历找出候选者（O(n)）， 第二遍验证（O(n)），总体 O(n)。

• ④ 欧拉筛：每个合数只被其最小质因子标记一次， 每个质数只被加入一次，总操作次数与 n 成正比，O(n)。

注意区分：埃氏筛是 O(n log log n)，而欧拉筛是严格的 O(n)。

常数对比：虽然四种算法都是 O(n)，但常数差异很大。 Base64 和 RLE 的常数较小，Boyer-Moore 需要两趟遍历（常数约 2）， 欧拉筛涉及取模运算常数略大。
