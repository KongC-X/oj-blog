1贪心算法核心思想

贪心算法（Greedy Algorithm）是一种在每一步选择中都采取当前状态下最优 （即局部最优）的选择，从而希望导致全局最优的算法策略。

贪心算法的基本特征

核心思想：分阶段决策，每阶段选取当前"最好"的选项，不回头调整。
适用条件：具有最优子结构和贪心选择性质。
  • 最优子结构：问题的最优解包含子问题的最优解
  • 贪心选择性质：通过局部最优选择能导出全局最优解
不适用场景：部分问题局部最优 ≠ 全局最优（如背包问题、最短路径等需要 DP 的场景）

🧠 记忆口诀

"鼠目寸光，步步为营" — 贪心只看眼前一步，不管未来如何。
"局部最优 ≠ 全局最优" — 不是所有问题都能用贪心，需要证明贪心选择性质。

贪心算法的解题框架

1 建立数学模型：将问题转化为"在一组候选解中选最优"的形式
2 确定贪心策略：定义"当前最优"的评价标准（如选最早结束、最小权值等）
3 模拟执行：按贪心策略逐一选择，得到一组解
4 验证正确性：判断该策略是否总能得到全局最优解
💡 初赛考查形式：不要求写出完整贪心代码，而是理解贪心策略的适用场景、 判断某问题能否用贪心解决、模拟贪心过程得出结果。

1.1 哈夫曼编码 — 一个经典的贪心策略

哈夫曼编码（Huffman Coding）是数据压缩中的经典算法，其本质就是一个贪心策略： 每次从频率集合中选出频率最小的两个节点合并，构造一棵带权路径长度最小的二叉树。

为什么哈夫曼编码是贪心？

贪心选择：每一步都合并当前频率最小的两个节点。
局部最优：每次合并使当前的总代价增量最小。
全局最优：通过这样的局部最优选择，最终得到的编码总长度（WPL）一定是最小的。

2021 年第 11 题直接考查了这一知识点。

📌 2021 第 11 题 · 原题结论： 哈夫曼编码的算法策略本质是贪心策略。

2区间选点问题

问题描述：给定若干个区间，选择尽可能少的点， 使得每个区间内至少包含一个被选中的点。

标准解法：贪心

策略：将所有区间按右端点从小到大排序。
依次处理每个区间：如果当前区间尚未被覆盖，则选其右端点作为一个新点。

正确性：选右端点可以"一箭多雕"——该点最有可能覆盖后续更多的区间。

示例演示

区间集合：{[1,3], [2,5], [4,6], [3,7], [6,8]}

按右端点排序后：[1,3]→[2,5]→[4,6]→[3,7]→[6,8]
执行过程：
  • 取区间 [1,3] 的右端点 3 → 覆盖了 [1,3] 和 [2,5]
  • 下一个未覆盖区间 [4,6]，取右端点 6 → 覆盖了 [4,6] 和 [3,7] 和 [6,8]
  • 所有区间都被覆盖
最少点数：2（点 3 和点 6）

3区间覆盖问题

问题描述：给定一个目标区间 [S, T] 和若干可用区间， 选择最少的区间来完全覆盖目标区间。

标准解法：贪心

策略：将所有区间按左端点从小到大排序。
每次从能覆盖当前起点的区间中，选出右端点最大的那个，然后更新起点为该右端点。

核心：选覆盖范围最大的区间，尽量减少需要的区间数量。

示例演示

目标区间 [1, 8]，可用区间：{[1,3], [2,5], [3,6], [4,7], [5,8], [6,9]}

排序后（按左端点）：[1,3], [2,5], [3,6], [4,7], [5,8], [6,9]
执行过程：
  • 起点 = 1，能覆盖 1 的区间有 [1,3] 和 [2,5]，选右端点最大的 [2,5]，更新起点 = 5
  • 起点 = 5，能覆盖 5 的区间有 [3,6], [4,7], [5,8], [6,9]，选右端点最大的 [6,9]，更新起点 = 9
  • 起点 = 9 ≥ 终点 8 → 覆盖完成
最少区间数：2（[2,5] 和 [6,9]）

4区间调度（活动安排）问题

问题描述：有若干个活动，每个活动有开始时间和结束时间， 同一时间只能参加一个活动，问最多能参加多少个互不重叠的活动。

标准解法：贪心

策略：将所有活动按结束时间从小到大排序。
依次选择：如果当前活动的开始时间 ≥ 上一个选中活动的结束时间，就选择它。

为什么按结束时间？结束越早，留给后面的时间越多，能安排的活动也越多。

三种区间问题策略对比
问题排序标准贪心策略
区间选点按右端点升序选未覆盖区间右端点
区间覆盖按左端点升序选能覆盖起点且右端最大的
区间调度按结束时间升序选结束最早且不与已选重叠的
💡 这三种区间问题是贪心算法的经典模型。初赛中常以概念辨析或模拟过程的形式考查—— 给定几个区间，让你模拟贪心过程并说出结果。

5贪心 vs 动态规划（DP）

贪心和动态规划（DP）都利用最优子结构性质，但二者有本质区别。

对比维度贪心（Greedy）动态规划（DP）
决策方式单向：每步选当前最优，不回头多向：考虑所有可能，对比选择
子问题依赖只依赖当前状态，不考虑未来依赖所有可能的子问题结果
是否回溯❌ 不回溯，一步定局✅ 通过状态转移比较不同路径
正确性保证需要证明贪心选择性质通过枚举所有可能保证最优
时间复杂度通常 O(n) 或 O(n log n)通常 O(n²) 或更高
典型问题哈夫曼编码、活动安排、Dijkstra背包问题、最长上升子序列、编辑距离
⚠️ 易混淆点

贪心不是 DP 的简单版！贪心做了"不可撤销"的决定，而 DP 会考虑所有可能性。
能用贪心解决的问题一定能用 DP 解决，但反之不一定。
判据：如果一个问题可以通过"选一个最优选项后，剩下的问题还能独立地按同样策略求解"，
则可能适合贪心；如果需要在多个选项中做对比取舍，则通常需要 DP。

🎯 记忆要点

贪心 = 一条路走到黑 — 每一步选最好的，不后悔
DP = 条条大路通罗马 — 先试所有可能的路径，再选最好的
关键区别：贪心不做决策比较，DP 显式比较所有子问题解

📝 真题 · 2021 · 第 11 题 哈夫曼编码与贪心策略
以下关于哈夫曼编码的描述，正确的是（ ）。
A 哈夫曼编码的算法本质是分治策略
B 哈夫曼编码的算法本质是贪心策略
C 哈夫曼编码的算法本质是动态规划
D 哈夫曼编码的算法本质是搜索策略
✅ 正确答案：B · 贪心策略
分析：

哈夫曼编码的构造过程是：每次从集合中选出频率最小的两个节点合并， 这一操作就是典型的贪心选择——每一步都选当前最优（频率最小）。

为什么 A（分治）不对？分治是把问题分解为独立的子问题再合并， 而哈夫曼编码并不"分解"问题，而是自底向上合并。

为什么 C（DP）不对？DP 需要枚举多个子问题的解并比较， 哈夫曼的每一步选择是确定的（最小两个），不需要从多种方案中挑选最优。

结论：哈夫曼编码的本质算法策略是 贪心策略。
📝 真题 · 2022 · 第 7 题 哈夫曼编码长度计算
假设有 5 个字母 A、B、C、D、E，它们的出现频率分别为 2、3、5、7、8。 构造哈夫曼树，则字母 A 的编码长度（二进制位数）为（ ）。
A 2
B 3
C 4
D 5
✅ 正确答案：B · 3
构造哈夫曼树过程：

初始频率：A=2, B=3, C=5, D=7, E=8

第 1 步：合并最小的 A(2) 和 B(3) → 新节点 N1=5（加入集合）
集合：N1=5, C=5, D=7, E=8

第 2 步：合并最小的 N1(5) 和 C(5) → 新节点 N2=10（加入集合）
集合：D=7, E=8, N2=10

第 3 步：合并最小的 D(7) 和 E(8) → 新节点 N3=15（加入集合）
集合：N2=10, N3=15

第 4 步：合并 N2(10) 和 N3(15) → 根节点 = 25

树的形态（左0右1）：
根(25)
/ \
N2(10) N3(15)
/ \ / \
N1(5) C(5) D(7) E(8)
/ \
A(2) B(3)

A 的路径：根 → N2(0) → N1(0) → A(0) → 共 3 位
路径：根→左(0) → N1左(0) → A(0)，编码为 000

各字母编码长度：
A=3位, B=3位, C=2位, D=2位, E=2位

结论：字母 A 的编码长度为 3。

✏️ 模拟题 · 活动安排 贪心选择最多活动
有 5 个活动，开始和结束时间如下（括号表示时间段）：
A(0,4)、B(3,6)、C(5,8)、D(6,9)、E(8,10)
用贪心算法（按结束时间最早）选择最多互不重叠的活动，最多可以选（ ）个？
A 2 个
B 3 个
C 4 个
D 5 个
✅ 正确答案：B · 3 个
贪心过程（按结束时间排序）：

按结束时间排序后的活动：
A(0,4) 结束=4 → B(3,6) 结束=6 → C(5,8) 结束=8 → D(6,9) 结束=9 → E(8,10) 结束=10

具体步骤：

处理活动时间开始≥上次结束？选择
1A(0,4)✅（第一个活动）✅ 选，上次结束 = 4
2B(3,6)❌ 3 < 4跳过
3C(5,8)✅ 5 ≥ 4✅ 选，上次结束 = 8
4D(6,9)❌ 6 < 8跳过

✏️ 模拟题 · 硬币找零 贪心找零策略

A 4 枚
B 5 枚
C 6 枚
D 7 枚
✅ 正确答案：C · 6 枚
贪心过程（每次选面值最大的硬币）：

步骤剩余金额选最大面值≤剩余硬币数
16325（剩余 38）1
23825（剩余 13）2
31310（剩余 3）3

✏️ 模拟题 · 贪心 vs DP 判断哪个问题适合用贪心
以下问题中，最适合用贪心算法求解的是（ ）。
A 0-1 背包问题（每个物品要么选要么不选）
B 活动安排问题（选最多互不重叠的活动）
C 最长公共子序列（LCS）
D 最短路径（Dijkstra 算法除外）
✅ 正确答案：B · 活动安排问题
逐一分析：

A. 0-1 背包问题 ❌ 不能用贪心。
0-1 背包不具备贪心选择性质。按"价值/重量比"选单位价值最高的物品， 未必能得到全局最优解。需要用 动态规划 求解。

B. 活动安排问题 ✅ 最适合贪心。
按"结束时间最早"贪心选择，可以证明能选出最多互不重叠的活动。 这是贪心算法的经典教材问题。

C. 最长公共子序列（LCS） ❌ 需要用 DP。
当前位置的最优解依赖于两个字符串前面所有位置的匹配情况， 每一步无法做出独立的最优决策。

D. 最短路径（Dijkstra 除外） ❌ 一般用 DP 或 BFS。
注意 Dijkstra 算法本身是一个贪心算法（每次选距离最小的未处理节点）， 但题目说"除外"。其他最短路径算法（如 Bellman-Ford、Floyd）不是贪心。

结论：活动安排问题是贪心算法的标准例题。

区分标准：贪心适合"每步选一个最优，剩下的仍然是独立的子问题"。 如果需要在多步决策之间比较取舍，就需要 DP。
✏️ 综合模拟 · 概念辨析 贪心算法综合判断
以下关于贪心算法的描述，错误的是（ ）。
A 贪心算法每一步都选择当前状态下的最优解
B 贪心策略需要证明其具有贪心选择性质
C 所有问题都可以用贪心算法求解
D 哈夫曼编码是一种贪心算法
✅ 正确答案：C · 所有问题都可以用贪心算法求解
逐一分析：

A. 贪心算法每一步都选择当前状态下的最优解
✅ 正确。这正是贪心算法的核心定义——"局部最优"选择。

B. 贪心策略需要证明其具有贪心选择性质
✅ 正确。贪心选择性质是指通过一系列局部最优选择可以得到全局最优解。 这是使用贪心算法的前提条件，必须证明才能保证正确性。

C. 所有问题都可以用贪心算法求解
❌ 错误。很多问题不具备贪心选择性质。 例如 0-1 背包问题、最短路径（带负权）、旅行商问题等， 贪心算法无法得到最优解，需要用 DP 或其他算法。

D. 哈夫曼编码是一种贪心算法
✅ 正确。每次合并频率最小的两个节点，是典型的贪心策略。

结论：C 是错误描述。
