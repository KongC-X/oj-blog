💡 霍夫曼编码就像设计电报密码

在电报时代，人们发现常用字（如"的"、"是"）出现频率很高，而冷僻字（如"爨"）很少用到。聪明的电报员想出了一个办法：经常用的字用短代码（如"00"），很少用的字用长代码（如"11111"）——这样整体上传输的电报码字最少。

这就是哈夫曼编码的核心思想！根据每个字符的出现频率来确定编码长度：频率高的用短码，频率低的用长码，从而达到整体压缩效果。

📊 直观对比

假设一篇文章中 A 出现50次、B出现30次、C出现10次、D出现10次：

  • 定长编码：全部用2位二进制（A=00, B=01, C=10, D=11）→ 总共需要 100×2 = 200 比特
  • 哈夫曼编码：A=0, B=10, C=110, D=111 → 总共需要 50×1+30×2+10×3+10×3 = 170 比特
  • 节省了 15% 的空间！

2 核心概念

2.1 哈夫曼树（最优二叉树）

哈夫曼树（Huffman Tree）是一种带权路径长度（WPL）最小的二叉树。给定 n 个叶子节点（每个有权值），构造出的 WPL 最小的二叉树就是哈夫曼树。

📐 关键术语
术语含义公式
权值 (Weight)叶子节点的权重（通常是频率）—
路径长度从根到该节点的边数—
WPL带权路径长度之和Σ(权值 × 路径长度)
前缀编码任何编码都不是另一个编码的前缀无歧义解码

2.2 前缀编码（Prefix Code）

哈夫曼编码是一种前缀编码：任何一个字符的编码都不是另一个字符编码的前缀。这样才能在变长编码的情况下无歧义地解码。

✅ 前缀编码示例

A=0, B=10, C=110, D=111 → "0110111" 只能解码为 "ABCD"

❌ 反例

A=0, B=01, C=1 → "01" 可以解码为 "AB" 或 "BA"，有歧义！

2.3 WPL 计算

WPL (Weighted Path Length) = Σ（每个叶子节点的权值 × 该节点到根的距离）

哈夫曼树的 WPL 是所有二叉树中最小的。我们通常用 WPL 来衡量数据压缩的效率。

2.4 变长编码 vs 定长编码

对比维度定长编码哈夫曼变长编码
编码长度所有字符相同频率高→短，频率低→长
空间效率固定最优（WPL最小）
解码方式按固定长度切分前缀码树遍历
适用场景字符均匀分布字符频率差异大

3 哈夫曼树的构造步骤

3.1 算法流程

🔧 构造步骤（经典算法）
  1. 排序：将所有节点按权值从小到大排序
  2. 合并：取出权值最小的两个节点，合并为一个新节点（权值为两者之和）
  3. 重复：将新节点放回集合，再次排序，重复步骤1-2
  4. 终止：直到只剩一个节点（根节点）

3.2 编码规则

📝 左0右1（约定俗成）

从根到叶子：左子树边标记为 0，右子树边标记为 1。每个叶子节点的哈夫曼编码就是从根到该叶子路径上的 0/1 序列。

C++ 
// 哈夫曼树节点定义
struct HuffmanNode {
    int weight;           // 权值（频率）
    char ch;              // 字符（可选）
    HuffmanNode* left;
    HuffmanNode* right;
    HuffmanNode(int w) : weight(w), ch(0), left(nullptr), right(nullptr) {}
};

// 构造哈夫曼树（使用优先队列）
HuffmanNode* buildHuffman(int weights[], int n) {
    auto cmp = [](HuffmanNode* a, HuffmanNode* b) { return a->weight > b->weight; };
    priority_queue<HuffmanNode*, vector<HuffmanNode*>, decltype(cmp)> pq(cmp);
    
    for (int i = 0; i < n; i++)
        pq.push(new HuffmanNode(weights[i]));
    
    while (pq.size() > 1) {
        HuffmanNode* left = pq.top(); pq.pop();
        HuffmanNode* right = pq.top(); pq.pop();
        HuffmanNode* parent = new HuffmanNode(left->weight + right->weight);
        parent->left = left; parent->right = right;
        pq.push(parent);
    }
    return pq.top(); // 返回根节点
}

3.3 重要性质

  • 哈夫曼树没有度为1的节点（严格二叉树 / 满二叉树）
  • n 个叶子节点 → 哈夫曼树共有 2n-1 个节点
  • 哈夫曼编码不唯一（左0右1可以互换，且相同权值的合并顺序可交换）
  • 哈夫曼编码是无损压缩，不是有损压缩

5 常见陷阱与易错点

⚠️ 陷阱 1：频率低的离根近？

错误理解：认为频率低的节点应该靠近根节点。
正解：恰恰相反！频率高的离根近（编码短），频率低的离根远（编码长）。这样才能让高频字符用短编码，整体 WPL 最小。

⚠️ 陷阱 2：哈夫曼编码是唯一的？

错误理解：哈夫曼编码方案是唯一确定的。
正解：哈夫曼编码不唯一！原因有两个：(1) 左右子树标记 0/1 可以互换，(2) 当有多个相同权值时，合并顺序可以不同。但WPL 一定相同且最小。

⚠️ 陷阱 3：哈夫曼编码是有损压缩？

错误理解：认为哈夫曼编码丢失了信息。
正解：哈夫曼编码是无损压缩！它能完全还原原始数据，因为前缀编码保证了无歧义解码。同义词：熵编码、统计编码。

⚠️ 陷阱 4：构造时选取最大的两个合并？

错误理解：合并权值最大的两个节点。
正解：每次必须选取权值最小的两个节点合并。这是保证 WPL 最小的关键！
