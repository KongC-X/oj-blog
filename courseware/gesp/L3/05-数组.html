GESP C++三级 · 数组

One-Dimensional Arrays — 连续内存中的数据序列

⚡ 8选择题+9判断题 📊 年均2~3道 ⭐ 约8%分值

1 第一步：情境导入 — 直观比喻

🎯 储物柜比喻

想象学校走廊有一排 编号的储物柜，编号从 0 开始：柜子[0]、柜子[1]、柜子[2]...

每个柜子放一件物品。你可以：打开柜子看里面有什么（读取），也可以往柜子里放新东西（写入），还可以清点所有柜子（遍历）。

在 C++ 中，数组 就是一排编号的储物柜，每个"柜子"存放一个 相同类型 的数据。柜子编号就是下标，从 0 开始，最后一个柜子编号是 n-1。

📦 数组 = 一排编号储物柜

下标 从 0 开始 → 访问 arr[i] → 个数 固定编译时确定

2 第二步：概念建构

🔵 数组定义方式
声明语句含义下标范围
int arr[5];声明5个int的数组0 ~ 4
int arr[4] = {1,2,3};初始化部分元素，arr[3]自动为00 ~ 3
int a[] = {1,2,3,4,5};省略大小，编译器自动推断为50 ~ 4
📐 三个核心特性
  • 内存连续存放：数组元素在内存中地址相邻，a[0] 紧挨着 a[1]，a[1] 紧挨着 a[2]...
  • 编译时确定大小：C++标准数组的大小必须在编译时就确定，不能用变量做大小（如 int n; cin>>n; int a[n]; 在标准C++中不允许）
  • 数组名是常量：数组名代表首地址，不能被赋值（不能写 arr = arr2;），但可以修改每个元素（arr[2] = 100;）

3 第三步：代码实战

📝 数组完整操作演示
cpp
#include <iostream>
using namespace std;

int main() {
    // 1. 定义并初始化数组 ← 高频考点！
    int arr[6] = {1, 2, 3, 4, 5, 6};

    // 2. 遍历数组（依次访问每个元素）
    cout << "原数组: ";
    for (int i = 0; i < 6; i++) {
        cout << arr[i] << " ";
    }
    cout << endl;

    // 3. 交换相邻元素（加法交换法）← 高频考点！
    for (int i = 0; i < 6; i += 2) {
        arr[i] = arr[i] + arr[i+1];      // 步骤A: a = a + b
        arr[i+1] = arr[i] - arr[i+1];    // 步骤B: b = a - b
        arr[i] = arr[i] - arr[i+1];      // 步骤C: a = a - b
    }
    cout << "交换后: ";
    for (int i = 0; i < 6; i++) {
        cout << arr[i] << " ";
    }
    // 输出: 2 1 4 3 6 5
    cout << endl;

    // 4. 数组下标越界：编译不会报错！← 高频考点！
    // arr[6] = 100;   // 越界！下标最大为5
    // cout << arr[10]; // 越界！运行时可能崩溃

    return 0;
}
🔍 代码要点逐行解读
  • int arr[6] = {1,2,3,4,5,6}; — 定义长度为6的整型数组并初始化所有元素
  • for (int i = 0; i < 6; i++) — 遍历数组的标准写法，i从0到5（len-1）
  • 交换相邻元素 — 运用加法交换法：a=a+b, b=a-b, a=a-b 完成交换
  • 越界访问 — C++编译器不检查下标越界，运行时行为未定义

5 第五步：陷阱警示

⚠️ 陷阱1：越界访问编译不报错，运行崩溃

C++编译器不会检查数组下标是否越界。程序可能"正常"运行，也可能直接崩溃，甚至产生诡异结果。这是初学者最容易犯的致命错误。

错误示范 int arr[5]; arr[5] = 100; → 下标应该是 0~4，5已经越界！

⚠️ 陷阱2：下标从 0 开始，不是 1

长度为 n 的数组，有效下标范围是 0 到 n-1。初学者经常以为最后一个元素是 arr[n]，实际上 arr[n] 是越界访问。

易错点 int arr[5]; 的最后一个元素是 arr[4]，不是 arr[5]！

⚠️ 陷阱3：数组名是常量，不能赋值

数组名代表数组在内存中的首地址，是常量。可以修改数组中某个元素的值，但不能对数组名赋值。

正确的 arr[2] = 100;（修改元素）  错误的 arr = {1,2,3};（不能整体赋值）

第1题 · 数组基本概念（2025/09 第3题）

以下关于C++数组的说法，错误的是（ ）

A. 数组的下标通常从0开始   B. int arr[5]; 声明了一个包含5个整数的数组
C. 数组的大小必须在编译时确定   D. 可以通过 arr[5] 来访问 int arr[5]; 数组的最后一个元素

答案：D
解析：arr[5]有5个元素，下标0~4，arr[4]才是最后一个元素，arr[5]是越界访问。
第2题 · 数组初始化和赋值（2025/09 第11题）

执行以下代码后，数组 arr 的内容是（ ）

int arr[4] = {1, 2, 3};
arr[3] = arr[0] + arr[2];

A. {1, 2, 3, 3}   B. {1, 2, 3, 4}   C. {1, 2, 3, 5}   D. {1, 2, 3, 6}

答案：B
解析：arr[3]=arr[0]+arr[2]=1+3=4。注意数组中未初始化的元素arr[3]初始为0，后被赋值。
第3题 · 下标越界行为（2026/03 第3题）

关于下列正确的程序段，说法正确的是（ ）

A. 数组下标越界访问会产生编译错误
B. 数组下标越界访问会抛出异常
C. 数组下标越界访问不会产生编译错误，但运行时行为未定义
D. 数组下标越界访问会自动扩展数组大小

答案：C
解析：C++不检查数组下标越界，编译能通过，但运行时可能崩溃或产生未定义行为。
第4题 · 一维数组特性（2025/12 第2题）

以下关于标准C++一维数组的描述，哪一项是错误的？（ ）

A. 数组的下标从0开始
B. 数组在内存中是连续存放的
C. 数组的长度只能在运行时才能确定
D. 可以在程序中修改数组某个元素的值

答案：C
解析：C错误，标准C++数组长度必须在编译时确定，不能使用运行时的变量值作为数组大小。
第5题 · 数组定义语法（2023/12 第1题）

下面C++数组的定义中，会丢失数据的是（ ）

A. char dict_key[] = {'p','t','o'};

C. char dict_name[]={'chen','wang','zhou'};
D. float dict_value[]={3,2,1};

答案：C

第6题 · 代码错误数量（2024/06 第11题）

以下C++代码中存在几处错误（ ）

const int SIZE = 5;
int arr[SIZE];
for (int i = 0; i <= SIZE; i++) {
    arr[i] = i * 2;
}
cout << arr[SIZE] << endl;

A. 0处   B. 1处   C. 2处   D. 3处

答案：C
解析：① i<=SIZE 导致当i=5时越界写入；② arr[SIZE] 访问下标5越界。共2处错误。
第7题 · 数组元素运算（2025/12 第7题）

以下代码执行后，输出的结果是（ ）

int arr[5] = {1, 2, 3, 4, 5};
int p = arr[1];
cout << (p + 2) << endl;

A. 1   B. 2   C. 3   D. 4

答案：D
解析：arr[1]=2（下标从0开始），p=2，p+2=4。
第8题 · 相邻元素交换（2025/12 第8题）

以下代码执行后，数组 arr 的内容是（ ）

int arr[6] = {1, 2, 3, 4, 5, 6};
for (int i = 0; i < 6; i += 2) {
    arr[i] = arr[i] + arr[i+1];
    arr[i+1] = arr[i] - arr[i+1];
    arr[i] = arr[i] - arr[i+1];
}

A. {2,1,4,3,6,5}   B. {1,2,3,4,5,6}
C. {3,1,4,2,5,3}   D. {1,3,2,5,4,6}

答案：A
解析：加法交换法：每次循环交换相邻两个元素。{1,2}→{2,1}，{3,4}→{4,3}，{5,6}→{6,5}，最终结果为 {2,1,4,3,6,5}。

判断题（共9题，轮换色：indigo→orange→purple→pink→teal→indigo→orange→purple→pink）

判断题第1题 · 内存存放（2025/12）

数组的所有元素在内存中可以不连续存放。（ ）

答案：错误
数组元素在内存中一定连续存放，这是数组最基本的特性。
判断题第2题 · 数组整体赋值

C++中可以对数组和数组的每个基础类型的元素赋值。（ ）

答案：错误
数组名不能作为整体被赋值（如 arr = arr2; 是非法的），但可以修改每个独立的元素。
判断题第3题 · 数组大小可调

在C++语言中，字符数组被定义时，它的大小可以调整。（ ）

答案：错误
数组大小在定义时确定，不能改变（标准数组是编译时静态大小）。
判断题第4题 · 查找最小值

对定义的数组 int a[7]={2,0,2,4,3,1,6}，可以用简单循环就找到其中最小的整数。（ ）

答案：正确
遍历数组，用变量记录当前最小值，一次遍历即可找到（最小值=0）。
判断题第5题 · 越界编译错误

在C++语言中，长度为n的数组，访问下标为n的元素会引起编译错误。（ ）

答案：错误
下标越界不会引起编译错误，运行行为未定义（可能崩溃、可能错误结果）。
判断题第6题 · 下标与内存关系

在C++语言中，数组下标的大小决定元素在逻辑上的先后顺序，与元素在内存中位置的先后顺序无关。（ ）

答案：错误
数组下标的大小直接对应元素在内存中的位置顺序，下标0在最低地址，依次递增。
判断题第7题 · 必须指定大小

在C++语言中，定义数组时，[]中必须指定元素个数。（ ）

答案：错误
int a[] = {1,2,3}; 可以不指定大小，编译器会根据初始化列表自动推断为3。
判断题第8题 · 数组名不可改变

在C++中，数组名不能改变，数组名不能被赋值。（ ）

答案：正确
数组名是常量，代表数组首地址，不能被赋值。
判断题第9题 · 省略大小的初始化

在C++中，int a[] = {1, 2, 3, 4, 5}; 可以定义一个包含5个元素的整型数组。（ ）

答案：正确
编译器根据初始化列表中的5个值，自动推断数组大小为5。
