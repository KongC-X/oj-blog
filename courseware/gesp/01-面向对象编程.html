Object-Oriented Programming（OOP）— 封装、继承、多态

1 第一步：生活引入 — 用汽车设计理解 OOP

🚗 从一个问题开始

想象你要设计一辆汽车。没有面向对象，几千行代码散落各处——改一个刹车灯可能要翻遍整个项目。就像把发动机、轮胎、方向盘全堆在一个仓库，谁都能碰，谁都能弄坏。

面向对象编程（OOP）给了我们一套组织代码的思维方式：把"汽车"抽象成类，把具体的一辆车叫做对象。

OOP 概念汽车类比说明
类（class）汽车设计蓝图定义汽车有什么属性（颜色、排量）和方法（启动、刹车）
对象（object）生产出来的实车同一张蓝图可以造出无数辆不同的车
封装（encapsulation）驾驶舱封闭，只暴露方向盘和踏板发动机复杂逻辑被隐藏，你只需踩油门
继承（inheritance）SUV 继承汽车，再加越野功能子类拥有父类所有能力，还可扩展
多态（polymorphism）踩刹车，不同车反应不同（油刹 vs 电刹）同一接口，不同实现
💡 一句话记住 OOP：类是模板，对象是实例；封装保安全，继承省重复，多态灵活用。
📖 OOP 的发展背景

面向对象编程起源于 1960 年代的 Simula 语言，真正流行是在 1990 年代随着 C++ 和 Java 的普及。它的诞生是为了解决面向过程编程在大型项目中的痛点：

  • 耦合度高：数据和操作分离，函数间互相依赖，改一个地方可能引发连锁错误
  • 代码复用困难：不同项目间很难直接复用代码，每次都要重写
  • 维护成本高：需求变化时需要修改大量已有代码，容易引入新 bug

OOP 通过类+对象的组织方式，把数据和操作封装在一起，让代码更加模块化、可维护、可复用。

🎯 为什么 GESP 六级考 OOP？

GESP 六级大纲明确要求掌握类与对象、封装、继承、多态、静态成员、虚函数等概念。这些是理解 C++ 高级特性的基础，也是从"写代码"到"设计代码"的关键跨越。在实际竞赛和工程中，OOP 思想能帮助你写出结构清晰、易于扩展的程序。

2 2. 核心概念详解

2.1 类与对象

定义格式

C++ 
class 类名 {
private:
    // 私有成员（仅类内部可访问）
    数据类型 成员变量;
    返回值类型 成员函数(参数列表);

protected:
    // 保护成员（类内部和子类可访问）

public:
    // 公有成员（任何地方都可访问）
    类名();          // 构造函数
    ~类名();         // 析构函数
    返回值类型 成员函数(参数列表);
};

创建对象

C++ 
// 直接在栈上创建
Student stu;
stu.showInfo();

// 在堆上创建（需要手动 delete）
Student *p = new Student("张三", 18);
p->showInfo();
delete p;

访问权限对照

访问权限 类内部 子类内部 类外部（通过对象）
private ✅ ❌ ❌
protected ✅ ✅ ❌
public ✅ ✅ ✅

代码示例

C++ 
#include <iostream>
#include <string>
using namespace std;

class Student {
private:
    string name;    // 私有：外部不能直接修改
    int age;
    int score;

public:
    // 构造函数：对象创建时自动调用
    Student(string n, int a, int s) {
        name = n;
        age = a;
        score = s;
        cout << "构造函数被调用：" << name << endl;
    }

    // 析构函数：对象销毁时自动调用
    ~Student() {
        cout << "析构函数被调用：" << name << endl;
    }

    // 公有接口：通过函数访问私有数据
    void showInfo() {
        cout << name << "，" << age << "岁，成绩：" << score << endl;
    }

    void setScore(int s) {
        if (s >= 0 && s <= 100) score = s;
    }

    int getScore() { return score; }
};

int main() {
    Student s1("小明", 16, 90);
    s1.showInfo();
    // s1.name = "小红"; // 错误！private 成员不可直接访问
    s1.setScore(95);
    cout << "修改后成绩：" << s1.getScore() << endl;
    return 0;
}
// 执行顺序：构造 → 使用 → 析构（main 结束时）
🔍 this 指针

this 是一个隐含的指针，指向当前调用成员函数的对象本身。每个非静态成员函数内部都可以使用 this。

C++
class Student {
public:
    void showInfo() {
        // this 指向调用该函数的对象
        cout << this->name;  // 等价于直接写 name
    }
    // 当参数名与成员变量名相同时必须用 this
    void setName(string name) {
        this->name = name;  // 左边是成员，右边是参数
    }
};
🧠 栈 vs 堆——对象的内存分配

栈上对象：Student stu; —— 内存自动分配和释放，速度快，但生命周期受限于作用域。超出花括号 {} 后自动调用析构函数。

堆上对象：Student *p = new Student(...); —— 手动分配和释放（delete p;），生命周期由你控制，但忘记 delete 会导致内存泄漏。

堆对象通过指针 p-> 访问成员，栈对象通过点号 stu. 访问成员——但本质完全相同。

2.2 构造函数与析构函数

构造函数特点

特性 说明
函数名 与类名相同，无返回值
自动调用 创建对象时自动执行
可重载 可以有多个构造函数（参数不同）
默认构造 若不写任何构造函数，编译器自动生成一个无参空构造
初始化列表 在函数体之前初始化成员，效率更高
C++ 
class Example {
private:
    const int a;       // const 成员必须在初始化列表初始化
    int &ref;          // 引用成员也必须用初始化列表
public:
    // 初始化列表语法：
    Example(int x, int y) : a(x), ref(y) {
        // 函数体
    }
};
📋 拷贝构造函数（Copy Constructor）

拷贝构造函数是一种特殊的构造函数，用已有的同类对象来初始化新创建的对象。形式为：类名(const 类名 &other)。

C++
class Student {
public:
    Student(string n, int a) : name(n), age(a) {}
    // 拷贝构造函数
    Student(const Student &other) : name(other.name), age(other.age) {
        cout << "拷贝构造: " << name << endl;
    }
};
Student s1("小明", 16);
Student s2 = s1;   // 调用拷贝构造函数

如果你不定义拷贝构造函数，编译器会生成一个默认拷贝构造，逐个字节复制成员（浅拷贝）。当类中有指针类型成员时，必须自己定义拷贝构造函数来实现深拷贝。

析构函数特点

特性 说明
函数名 ~类名，无参数无返回值
自动调用 对象销毁时自动执行
唯一 每个类只有一个析构函数（不可重载）
资源释放 用于释放动态内存、关闭文件等

继承中的构造与析构顺序

C++ 
class Base {
public:
    Base() { cout << "Base 构造\n"; }
    ~Base() { cout << "Base 析构\n"; }
};

class Derived : public Base {
public:
    Derived() { cout << "Derived 构造\n"; }
    ~Derived() { cout << "Derived 析构\n"; }
};

int main() {
    Derived d;
    return 0;
}
// 输出：
// Base 构造
// Derived 构造
// Derived 析构
// Base 析构

关键规律：构造从基类到派生类（先父后子），析构从派生类到基类（先子后父）。

2.3 静态成员

静态成员用一个 static 关键字声明，属于类本身，而不是属于某个对象。所有对象共享同一份。

C++ 
class Counter {
private:
    static int count;  // 静态成员变量声明

public:
    Counter() { count++; }
    ~Counter() { count--; }

    static int getCount() { return count; }  // 静态成员函数
};

// 静态成员变量必须在类外单独定义初始化
int Counter::count = 0;

int main() {
    cout << "当前对象数：" << Counter::getCount() << endl;  // 0
    Counter c1, c2;
    cout << "当前对象数：" << Counter::getCount() << endl;  // 2
    { Counter c3; }
    cout << "当前对象数：" << Counter::getCount() << endl;  // 2（c3 已析构）
    return 0;
}

静态成员要点：

要点 说明
类外定义 静态成员变量必须在类外单独定义和初始化
通过类名访问 类名::静态成员 或通过对象 . 运算符
静态函数 只能访问静态成员，不能访问普通成员（没有 this 指针）
共享性 所有对象共享同一份，修改一个全部改变
🔧 静态常量成员（const static）

如果静态成员同时是 const 且是整数或枚举类型，可以在类内部直接初始化，不需要到类外定义：

C++
class Math {
public:
    const static double PI = 3.14159;   // ❌ 浮点数不能类内初始化
    const static int MAX = 100;          // ✅ 整型可以类内初始化
};
🧠 RAII（资源获取即初始化）

RAII 是 C++ 中一种重要的编程思想：在构造函数中获取资源（如内存、文件句柄），在析构函数中释放资源。这样资源管理被绑定到对象的生命周期上，对象销毁时资源自动释放，避免了手动管理带来的泄漏问题。

例如上面的 BankAccount 类，如果它有动态内存成员，就应该在析构函数中释放。这也是为什么基类析构函数通常要声明为 virtual 的原因之一。

3 3. 三大特性详解

3.1 封装（Encapsulation）

封装是将数据和操作数据的方法捆绑在一起，并对外隐藏内部实现细节。对外只暴露必要的接口。

C++ 
class BankAccount {
private:
    double balance;          // 余额对外隐藏

public:
    BankAccount(double init) : balance(init) {}

    // 对外只暴露操作接口
    void deposit(double m) {       // 存款
        if (m > 0) balance += m;
    }

    bool withdraw(double m) {      // 取款（带安全检查）
        if (m > 0 && m <= balance) {
            balance -= m;
            return true;
        }
        return false;
    }

    double getBalance() { return balance; }
};

封装的好处： - 保护数据不被外部随意篡改 - 内部实现改变不影响外部调用（比如修改利息计算方式） - 降低耦合，便于维护

3.2 继承（Inheritance）

继承让一个类（派生类）拥有另一个类（基类）的成员，并可以添加或重写。

三种继承方式

继承方式 基类 private → 派生类 基类 protected → 派生类 基类 public → 派生类
public 继承 不可访问 protected public
protected 继承 不可访问 protected protected
private 继承 不可访问 private private
C++ 
class Base {
private:
    int a;
protected:
    int b;
public:
    int c;
};

// public 继承
class PubDerived : public Base {
    // a 不可访问
    // b 是 protected
    // c 是 public
};

// protected 继承
class ProDerived : protected Base {
    // a 不可访问
    // b 是 protected
    // c 是 protected
};

// private 继承
class PriDerived : private Base {
    // a 不可访问
    // b 是 private
    // c 是 private
};

派生类调用基类构造函数

C++ 
class Base {
public:
    Base(int x) { cout << "Base(" << x << ")\n"; }
};

class Derived : public Base {
public:
    // 必须在初始化列表中调用基类构造函数
    Derived(int x, int y) : Base(x) {
        cout << "Derived(" << y << ")\n";
    }
};

如果不显式调用，会调用基类的默认无参构造函数；如果基类没有默认构造，则必须显式调用。

🚨 菱形继承与虚继承

当两个派生类继承同一个基类，又有一个类同时继承这两个派生类时，形成菱形继承（Diamond Inheritance）：

C++
class A { public: int val; };
class B : public A { };
class C : public A { };
class D : public B, public C { };
// D d; d.val;  // ❌ 二义性！不知道来自 B::val 还是 C::val

解决方法：使用虚继承（virtual inheritance），让 B 和 C 虚继承自 A，确保 A 的成员在 D 中只有一份拷贝。

C++
class B : virtual public A { };
class C : virtual public A { };
class D : public B, public C { };
// D d; d.val;  // ✅ 唯一确定，来自最顶层的 A

考试常考：菱形继承会导致基类成员在派生类中有多份拷贝，使用 virtual 继承可解决二义性。

3.3 多态（Polymorphism）

多态让同一个调用在不同的对象上产生不同的行为。

虚函数

C++ 
class Animal {
public:
    virtual void speak() {    // virtual 关键字
        cout << "动物发出声音" << endl;
    }
};

class Dog : public Animal {
public:
    void speak() override {   // override 表示重写（C++11 推荐）
        cout << "汪汪！" << endl;
    }
};

class Cat : public Animal {
public:
    void speak() override {
        cout << "喵喵！" << endl;
    }
};

int main() {
    Animal *p;
    Dog d;
    Cat c;

    p = &d;
    p->speak();   // 调用 Dog::speak → 汪汪！
    p = &c;
    p->speak();   // 调用 Cat::speak → 喵喵！
    return 0;
}

虚函数工作原理（vptr + vtable）：每个含有虚函数的类会生成一张虚函数表（vtable），表中按声明顺序存放所有虚函数的地址。每个对象中有一个隐式的虚指针（vptr）指向该类对应的 vtable。

🧠 虚函数调用过程分解

当通过基类指针调用虚函数时，运行时的执行流程：

  1. 通过指针找到对象
  2. 通过对象的 vptr 找到所在类的 vtable
  3. 通过 vtable 中找到对应的函数地址
  4. 跳转到该地址执行实际的函数

这个过程叫做动态绑定（dynamic binding/晚期绑定）。相比普通函数的静态绑定（编译期确定），动态绑定多了一次间接寻址，有轻微性能开销，但带来了极大的灵活性。

⚠️ 重要考点：构造函数不能是虚函数

原因：对象的 vptr 是在构造函数执行期间才初始化的。在构造函数执行之前，vptr 还不存在（或指向错误的位置），因此虚函数机制在构造期间尚未建立。如果构造函数是虚函数，将无法通过 vptr 调用它——这就成了"先有鸡还是先有蛋"的悖论。

记忆技巧：构造函数负责初始化 vptr，所以它自己不能依赖 vptr。

纯虚函数与抽象类

C++ 
class Shape {          // 抽象类（含纯虚函数）
public:
    virtual double area() = 0;     // 纯虚函数，不实现
    virtual void draw() = 0;
};

class Circle : public Shape {
private:
    double r;
public:
    Circle(double r) : r(r) {}
    double area() override { return 3.14 * r * r; }
    void draw() override { cout << "画一个圆\n"; }
};

// Shape s; // 错误！不能实例化抽象类
Circle c(5);  // 正确
概念 要点
纯虚函数 virtual 返回值 函数名() = 0;
抽象类 含至少一个纯虚函数的类，不能创建对象
具体类 实现了所有纯虚函数的派生类，可以创建对象

虚析构函数

当通过基类指针删除派生类对象时，如果析构函数不是虚函数，派生类析构函数不会调用，导致资源泄漏。

C++ 
class Base {
public:
    virtual ~Base() {   // 虚析构函数
        cout << "Base 析构\n";
    }
};

class Derived : public Base {
private:
    int *data;
public:
    Derived() { data = new int[100]; }
    ~Derived() override {
        delete[] data;    // 释放动态内存
        cout << "Derived 析构\n";
    }
};

int main() {
    Base *p = new Derived();
    delete p;   // 若~Base非虚，只调用Base析构，不会释放data
    return 0;
}

规则：如果类用作基类，且通过基类指针删除派生类对象，则基类析构函数必须声明为虚函数。

4.2 虚函数调用过程推演

C++ 
#include <iostream>
using namespace std;

class Base {
public:
    void f1() { cout << "Base::f1\n"; }
    virtual void f2() { cout << "Base::f2\n"; }
    virtual void f3() { cout << "Base::f3\n"; }
};

class Derived : public Base {
public:
    void f1() { cout << "Derived::f1\n"; }      // 隐藏（非虚）
    void f2() override { cout << "Derived::f2\n"; }  // 重写
    void f3() override { cout << "Derived::f3\n"; }
};

int main() {
    Derived d;
    Base *p = &d;

    p->f1();     // ①
    p->f2();     // ②
    p->f3();     // ③
    d.f1();      // ④
    return 0;
}

5 5. 常见陷阱

🚨 陷阱 1：基类析构函数不是虚函数
C++ 
class Base {
public:
    ~Base() { cout << "~Base\n"; }
};

class Derived : public Base {
    int *p = new int[100];
public:
    ~Derived() { delete[] p; cout << "~Derived\n"; }
};

Base *b = new Derived();
delete b;   // 只调用了 ~Base！！内存泄漏！

修复：基类析构函数前加 virtual。

🚨 陷阱 2：构造函数中调用虚函数
C++ 
class Base {
public:
    Base() { f(); }
    virtual void f() { cout << "Base::f\n"; }
};

class Derived : public Base {
public:
    Derived() : Base() {}
    void f() override { cout << "Derived::f\n"; }
};

Derived d;  // 输出 Base::f，不是 Derived::f

原因：构造函数执行时，对象的 vptr 指向当前正在构造的类的虚表，尚未指向派生类。构造和析构期间不要调用虚函数。

🚨 陷阱 3：混淆隐藏（hide）与重写（override）
C++ 
class Base {
public:
    virtual void f(int x) { }
};

class Derived : public Base {
public:
    void f() { }          // 隐藏了 Base::f(int)，不是重写！
    // 使用 override 关键字会让编译器报错：
    // void f() override { }  // 错误：no matching function to override
};

区别：重写要求函数签名完全一致（包括参数列表），隐藏只要求函数名相同。

🚨 陷阱 4：静态成员函数访问非静态成员
C++ 
class Demo {
    int x;
public:
    static void show() {
        cout << x;   // 错误！静态函数不能访问非静态成员
    }
};

原因：静态函数没有 this 指针，不知道访问哪个对象的成员。只能访问静态成员。

🚨 陷阱 5：拷贝构造函数中的浅拷贝问题
C++ 
class StringWrapper {
private:
    char *str;
public:
    StringWrapper(const char *s) {
        str = new char[strlen(s) + 1];
        strcpy(str, s);
    }
    ~StringWrapper() { delete[] str; }
};

int main() {
    StringWrapper s1("hello");
    StringWrapper s2 = s1;  // 浅拷贝：s1.str == s2.str
    return 0;               // 析构时 double free！
}

修复：定义拷贝构造函数，实现深拷贝——为新对象分配独立的内存并复制内容。

C++ 
StringWrapper(const StringWrapper &other) {
    str = new char[strlen(other.str) + 1];
    strcpy(str, other.str);  // 深拷贝：各自独立的内存
}

考试常考：类中有指针成员时，必须自定义拷贝构造函数和拷贝赋值运算符，否则会导致双重释放（double free）或悬挂指针。

    for (int i = 0; i < 3; ++i) { delete instruments[i]; }  // ❌ 越界访问！
