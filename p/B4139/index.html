题目描述

小明最近迷上了字符串操作。对每个字符串，小明每次可以执行以下两种操作之一：

  1. 把字符串的某个字符改成任意一个其他字符，花费 111 的代价；
  2. 交换字符串中的两个字符，花费 000 的代价。

小明发现，把一个字符串通过一系列的操作，可以转换成任何一个与之等长的字符串。

例如，把 hello\tt hellohello 变为 world\tt worldworld 的一种代价为 333 的操作序列如下：
\gdef\ar{\rightarrow}

  1. hello\arwello\tt \red hello \ar \red wellohello\arwello（替换 h\tt hh 为 w\tt ww，代价为 111）。
  2. wello\arwolle\tt w\blue ell\blue o\ar w\blue oll\blue ewello\arwolle（交换 e\tt ee 和 o\tt oo，代价为 000）。
  3. wolle\arworle\tt wo\red lle \ar wo\red rlewolle\arworle（替换 l\tt ll 为 r\tt rr，代价为 111）。
  4. worle\arworld\tt worl\red e \ar worl\red dworle\arworld（替换 e\tt ee 为 d\tt dd，代价为 111）。

小明发现，无法用少于 333 次的代价将 hello\tt hellohello 变为 world\tt worldworld。

显然，不同的转换方案花费的代价是不同的，请编程帮助小明计算把一个字符串变为另一个字符串的最小代价。

AC 代码

#include <iostream>
using namespace std;

int main() {
    int n, s;
    cin >> n >> s;

    int cnt1[26] = {0}, cnt2[26] = {0};

    // 生成第一个字符串
    for (int i = 0; i < n; ++i) {
        s = (s * 345) % 19997;
        int ch = 97 + (s % 26);
        cnt1[ch - 97]++;
    }

    // 生成第二个字符串
    for (int i = 0; i < n; ++i) {
        s = (s * 345) % 19997;
        int ch = 97 + (s % 26);
        cnt2[ch - 97]++;
    }

    int match = 0;
    for (int i = 0; i < 26; ++i) {
        match += min(cnt1[i], cnt2[i]);
    }

    cout << n - match << endl;
    return 0;
}
